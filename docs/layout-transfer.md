# Экспорт и импорт макетов

Доступно начиная с интеграции **1.0.0**. После обновления перезапустите HA
и обновите страницу браузера. Перепрошивка экранов не требуется.

Откройте **Настройки → Устройства и службы → GTag Display → шестерёнка
«Настроить / Configure» у нужного экрана**. В меню доступны настройка макета,
экспорт текущего макета и импорт файла.
[Описание готовых макетов с примерами](screens.md).

## Сохранить или поделиться

1. Выберите **Экспортировать текущий макет** и задайте название.
2. Нажмите **Скачать gtag-layout.json**. После Submit ссылка появится повторно.
   Ссылка доступна 20 минут, до перезапуска HA. Сам скачанный файл не имеет
   срока действия; его можно переименовать и передать другому пользователю.
3. Экспорт не изменяет экран и не отправляет данные на плату.

В файл входят макет, подписи, единицы, число знаков после запятой, интервал
обновления и время появления значка устаревания. Для графика сохраняется период
истории; для погоды — выбранная погодная сущность. История и прогноз в файл
не записываются: после импорта они берутся из HA получателя. Для пользовательского макета
сохраняются элементы, шаблоны текста и флаг `auto_update`.
Сохраняется текущий макет, включая более поздний вызов `draw`, а не только
последний стандартный макет из настроек. Устройство может быть вне радиосвязи.

В файле есть ID используемых сущностей HA и содержимое ваших шаблонов.
Аппаратные настройки, адрес платы, служебные ID записей интеграции и текущие
значения датчиков автоматически не добавляются. Тестовая картинка, переданная
как готовый framebuffer, не является редактируемым макетом и не экспортируется.

## Перенести на другой экран

1. В настройках целевого экрана выберите **Импортировать макет из файла**.
2. Загрузите сохранённый JSON (не более 256 КиБ).
3. Для каждой исходной сущности выберите соответствующую сущность на своей
   установке HA. Если исходный ID существует здесь, он предлагается по умолчанию;
   его можно заменить. Несколько исходных сущностей могут использовать один
   источник. Для макета часов этот шаг не нужен.
4. Проверьте предпросмотр с текущими данными выбранных сущностей.
   **Изменить → Сопоставить сущности заново** позволяет исправить выбор.
   **Изменить → Изменить настройки макета** открывает стандартные настройки.
5. Нажмите **Применить**. Изменится только целевой экран. Отмена до применения
   оставляет действующий макет и его настройки без изменений.

Макет сохраняется после перезапуска HA. Если плате временно недоступна связь,
настройки остаются сохранёнными для следующей передачи, как при обычной настройке.
Файл не привязан к Bluetooth или Zigbee: его можно использовать с обоими.

## Пользовательские шаблоны

Переназначаются полные ID сущностей в строках Jinja и обращения вида
`states.sensor.temperature.state`. Это работает в `states`, `state_attr`,
`is_state`, `expand`, списках и переменных с явно заданными ID.
Замена одновременная: можно поменять две сущности местами. Обычный текст,
комментарии, блоки `raw` и подписи стандартных макетов не переписываются.

Имена, вычисляемые шаблоном, например `'sensor.' ~ room`, а также выборки по
областям, устройствам и меткам сохраняются как есть: их нужно адаптировать
в самом шаблоне. Такие ссылки не предлагаются как отдельные поля сопоставления.
Макеты не сохраняют снимок значений: Jinja продолжает вычисляться на целевой HA.

## Формат файла

UTF-8 JSON с явной версией. Неизвестные версии и некорректные настройки
отклоняются до применения. Минимальный пример:

```json
{
  "format": "gtag-display-layout",
  "version": 1,
  "name": "Часы",
  "screen": {
    "preset": "clock",
    "update_interval": 30,
    "stale_after": 5
  }
}
```

Для стандартных макетов `screen` содержит те же параметры, что интерфейс:
`entity_1`, `label_1`, `unit_1`, `decimals_1` и при необходимости второй набор.
Для пользовательского: `preset: "custom"`, объект `layout` со схемой действия
[`draw`](screens.md#свой-экран) и `auto_update`.

Автоматические проверки используют реальные options flow, загрузку файлов HA,
HTTP-скачивание, шаблоны и сохранение настроек. Проверяются перенос между двумя
экранами, Zigbee, отмена, перезапуск и непрерывное отслеживание новых сущностей.
