# Обновление: рендеринг простых шаблонов на устройстве

Локальная сборка прошивки **1.2.0-dev.2**, протокол кадров **1**.
Кодек **2 — three_values_v1** сохранён для трёх полей;
кодек **3 — simple_templates_v1** добавляет часы с датой, часы с двумя
показателями и один крупный показатель. Погода и график не изменены.
Это ещё не опубликованный релиз. Версия интеграции в manifest.json остаётся
1.1.1; нужные изменения находятся в локальном архиве из `dist`.

## Порядок обновления

1. Распакуйте `gtag-ha-integration.zip` в `/config/` Home Assistant с заменой
   файлов. Итоговый путь: `/config/custom_components/gtag_ble_test/manifest.json`.
   Замените папку интеграции целиком, включая `fonts`, и перезапустите HA.
2. Для Zigbee замените внешний конвертер на `gtag-display.mjs` из этого же
   комплекта и перезапустите Zigbee2MQTT.
3. Прошейте UF2 своей платы. Готовые Pro Micro UF2 используют GPIO LCD
   `P0.11 / P1.04 / P1.06 / P1.13` и измерение аккумулятора на `P0.31`;
   Super52840 — `P1.15 / P1.13 / P1.14 / P1.12` без измерения аккумулятора.
   При другой разводке, калибровке или настройках соберите прошивку из
   соответствующего архива `sources/`, сохранив свои параметры.
   Для Wi-Fi используйте исходники, свои GPIO, имя устройства и `secrets.yaml`;
   универсального готового BIN с учётными данными здесь нет.
4. В GTag Display выберите один из четырёх шаблонов с отметкой 🌿 и обновите
   экран. В диагностике должна появиться прошивка `1.2.0-dev.2`, маска
   `firmware_capabilities.codecs: 15`, в списке — `three_values_v1`
   и `simple_templates_v1`. Для трёх полей ожидается `codec: 2`,
   для остальных трёх простых макетов — `codec: 3`.

Для сборки исходников используется ESPHome **2026.9.0**. Распакуйте архив
полностью: локальный YAML ссылается на соседние `packages/` и `components/`.
Публичные YAML и мастер HA пока закреплены на опубликованном `v1.1.1`;
они не скачивают новую локальную прошивку автоматически.

Плата получает ID шаблона, его ревизию и готовые строки. HA вычисляет
значения сущностей, единицы, округление, время и дату.
Рамки, положение текста и растровые шрифты находятся в прошивке.

Старые устройства продолжают получать изображение через RAW/RLE. Новая
прошивка также принимает кадры от старой интеграции и старого конвертера.
На `dev.1` три поля по-прежнему используют кодек 2, остальные макеты — RAW/RLE.
Для неподдерживаемых символов, отличающегося макета или крупного значения,
которое требует уменьшения шрифта с 44, HA автоматически
передаёт изображение. Перенастраивать экраны при обновлении или откате не нужно.
В Zigbee bitmap сохраняется в MQTT для старых конвертеров, а новый конвертер
отправляет по радио компактный пакет.

| Контрольный макет | Полезная нагрузка |
|---|---|
| Часы и дата | 27 байтов |
| Часы и два показателя | 81 байт |
| Один крупный показатель | 36 байтов |
| Три поля с CO₂, температурой и влажностью | 78 байтов |

RAW занимает 4096 байтов; размер строк и сжатого изображения зависит от текста.
Проверка CRC и подтверждение вывода на LCD сохраняются.

Все три nRF-профиля `dev.2` пересобраны на ESPHome 2026.9.0.
26 сентября прошли 334 теста HA, 67 нативных тестов, 38 проверок
конвертера Zigbee2MQTT и 18 проверок интерфейса.
Новые шаблоны сравниваются с Pillow и C++ побайтно, включая все дни недели;
проверяются RAW/RLE после отката на старую прошивку, ошибки пакетов и CRC.
Все глифы, метрики и кернинг перепакованных шрифтов сравнены с замороженными
ресурсами. Прежний файл `template_v1.bin` не изменён.

| Профиль | Занято flash | Занято RAM |
|---|---|---|
| Pro Micro Zigbee | 548 364 Б / 540 КиБ | 65 800 Б / 256 КиБ |
| Pro Micro Bluetooth | 434 208 Б / 540 КиБ | 40 496 Б / 256 КиБ |
| Super52840 Zigbee | 536 632 Б / 536 КиБ | 64 944 Б / 256 КиБ |

Лимиты flash в таблице учитывают консервативную границу UF2 `0xAD000`,
а не более широкие разделы из отчёта линкера. На nice!nano с загрузчиком 0.6.0
прежний большой UF2 записывался лишь частично; используйте обновлённые файлы.
Драйвер ESP32 Wi-Fi проверен нативными тестами с новым кодеком.

Адреса всех блоков UF2 проверены: начало `0x26000` для Pro Micro и `0x27000`
для Super52840, конец не выше `0xAD000`, без блоков загрузчика.
Конец Pro Micro Zigbee — `0xABF00`, запас до границы UF2 — 4352 байта.
В `dist` нет экспериментальных прошивок с тактированием LCD от nRF.
**Сборка `dev.2` ещё не проверена на физической плате.**

## Подтверждённая работа предыдущей dev.1

26 сентября компактная Zigbee-сборка `dev.1` записана на nice!nano с загрузчиком 0.6.0
и S140 6.1.1. После повторного входа в загрузчик обратное чтение CURRENT.UF2
подтвердило все 2057 блоков приложения, версию `1.2.0-dev.1` и неизменность
SoftDevice. Конец приложения — `0xA6900`, ниже предела `0xAD000`.
После обновления конвертера пользователь подтвердил работу нового режима.
Один и тот же кадр с CRC `f0154bfe` передан сначала через RLE (1390 байтов,
11,777 с по Zigbee2MQTT), затем через кодек 2 (80 байтов, 2,023 с).
Обе передачи завершились `displayed`, без повторов; полное время HA
сократилось с 13,82 до 6,43 с. Это проверка конкретного кадра и радиосвязи,
а не измерение расхода аккумулятора.
Подробности протокола: [firmware-compatibility.md](firmware-compatibility.md).

Прежнее содержимое `dist` сохранено в
`.local-artifacts/dist-before-cleanup-20260925-160804.zip` в корне проекта.
