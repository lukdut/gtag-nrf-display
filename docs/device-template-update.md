# Обновление: рендеринг простых шаблонов на устройстве

Начиная с **1.2.0** устройство может рисовать четыре шаблона с отметкой 🌿:
часы с датой, часы с двумя показателями, один крупный показатель и три поля.
HA передаёт ID шаблона и готовые строки; плата рисует рамки и текст.
Погода и график передаются изображением.

## Порядок обновления

Файлы доступны в [релизе v1.3.0](https://github.com/lukdut/gtag-nrf-display/releases/tag/v1.3.0).

1. Обновите интеграцию через HACS либо распакуйте `gtag-ha-integration.zip`
   в `/config/` Home Assistant с заменой всей папки `custom_components/gtag_ble_test`,
   включая `fonts`. Перезапустите HA; версия интеграции должна быть **1.3.0**.
2. Для Zigbee замените внешний конвертер на `gtag-display.mjs` из этого же
   релиза и перезапустите Zigbee2MQTT. Повторное сопряжение не требуется.
3. Обновите прошивку платы. Готовые Pro Micro UF2 используют GPIO LCD
   `P0.11 / P1.04 / P1.06 / P1.13` и измерение аккумулятора на `P0.31`
   через внешний делитель. Если делителя нет, отключите измерение в
   [мастере прошивки](firmware-wizard.md) и соберите свой вариант.
   Super52840 использует `P1.15 / P1.13 / P1.14 / P1.12` без измерения батареи.
   При другой разводке или калибровке также нужна собственная сборка.
4. Выберите шаблон с отметкой 🌿 и обновите экран. В диагностике ожидаются
   `firmware_version: 1.3.0`, `firmware_capabilities.codecs: 15`,
   `three_values_v1` и `simple_templates_v1` в списке кодеков.
   Три поля используют `codec: 2`, остальные три простых макета — `codec: 3`.

Мастер HA и публичные YAML закреплены на `v1.3.0`. В ранее сохранённом YAML
замените прежний тег на `v1.3.0` во всех ссылках пакетов, включая
`zigbee-no-battery.yaml`, сохранив свои GPIO, настройки батареи и подключения.
Для сборки используется ESPHome **2026.9.0**.

## Какой файл выбрать

| Файл релиза | Назначение |
|---|---|
| `gtag-ha-integration.zip` | Интеграция Home Assistant |
| `gtag-display.mjs` | Внешний конвертер Zigbee2MQTT |
| `gtag-zigbee.uf2` | Pro Micro / Super Mini / nice!nano, Zigbee |
| `gtag-display.uf2` | Та же плата, Bluetooth |
| `gtag-super52840-zigbee.uf2` | Super52840, Zigbee, загрузчик S140 v7 |
| `gtag-zigbee-esphome.zip` | Исходники Pro Micro Zigbee |
| `gtag-display-esphome.zip` | Исходники Pro Micro Bluetooth |
| `gtag-super52840-zigbee-esphome.zip` | Исходники Super52840 Zigbee |
| `gtag-esp32-c3-wifi-esphome.zip` | Исходники ESP32-C3 Wi-Fi |
| `SHA256SUMS` | Контрольные суммы файлов |

Распаковывайте архив исходников полностью: локальный YAML ссылается на
соседние `packages/` и `components/`. Для Wi-Fi задайте свои GPIO, имя устройства
и `secrets.yaml`; готового универсального BIN нет.
В локальном комплекте `dist` архивы исходников находятся в папке `sources/`.

## Когда передаётся изображение

HA сравнивает результат рендеринга на устройстве с предпросмотром побайтно.
Неподдерживаемые символы, изменённая геометрия или крупное значение,
для которого нужно уменьшить шрифт с 44, вызывают переход на RAW/RLE.
Для таких данных на экране предпросмотра появляется предупреждение.
Оно не мешает сохранить макет или отправить изображение; сокращение текста
или числа знаков после запятой может вернуть компактную передачу.

Предупреждение проверяет текущие данные и макет. Поддержка прошивки и
конвертера определяется при отправке; фактический режим виден в `codec`.
Старые устройства продолжают получать изображение. Новая прошивка также
работает со старой интеграцией и конвертером. Перенастройка экранов не нужна.
Протокол кадров остаётся **1**, CRC и подтверждение вывода на LCD сохранены.
