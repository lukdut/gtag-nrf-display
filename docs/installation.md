# Установка GTag Display

Репозиторий: **https://github.com/lukdut/gtag-nrf-display**.
Текущий релиз — **0.8.0**, поддерживается Bluetooth.
Интеграция проверена на Home Assistant 2026.9.2. Техническое имя
`gtag_ble_test` сохранено: существующие устройства и сущности остаются на месте.

## Интеграция через HACS

1. В HACS откройте меню → **Пользовательские репозитории / Custom repositories**.
2. Добавьте `https://github.com/lukdut/gtag-nrf-display`, тип **Integration**.
3. Найдите **GTag Display**, скачайте релиз и перезапустите Home Assistant.
4. Добавьте обнаруженный **GTag Display** через **Настройки → Устройства и службы**.
   Нужен Bluetooth-адаптер или прокси с поддержкой активных подключений.
5. Нажмите шестерёнку **Настроить / Configure** справа от записи интеграции,
   выберите макет и сущности, проверьте предпросмотр и примените настройки.

При переходе с ручной установки 0.7.1 удалять запись интеграции не нужно.
HACS обновляет тот же каталог `/config/custom_components/gtag_ble_test/`.
Радиопротокол и драйвер не изменены: уже работающую плату перепрошивать не нужно.

Пользовательский репозиторий HACS доступен без включения в общий каталог.
[Инструкция HACS](https://www.hacs.xyz/docs/faq/custom_repositories/).
Фактическую установку и обновление через интерфейс HACS ещё нужно проверить
на пользовательской системе; программные проверки её не заменяют.

## Сборка прошивки через ESPHome

Используйте **ESPHome Device Builder**. В HA OS это приложение/add-on ESPHome;
при HA Container ESPHome можно запустить в обычном Docker-контейнере либо
на другом компьютере. Собственный сборщик GTag не требуется.
[Способы установки ESPHome](https://esphome.io/install/).

Проверенная версия ESPHome — **2026.8.2**, nRF Connect SDK — **2.9.2**.
Более новые версии ESPHome не считаются проверенными автоматически.

1. Создайте новую конфигурацию в ESPHome Device Builder.
2. Замените её содержимое следующим YAML:

   ```yaml
   substitutions:
     gtag_name: gtag-kitchen
     gtag_friendly_name: "Экран кухни"
     gtag_battery_calibration: "1.0"

   packages:
     gtag: github://lukdut/gtag-nrf-display/config/esphome/packages/ble.yaml@v0.8.0
   ```

3. Если внешний делитель аккумулятора не установлен, дополнительно вставьте:

   ```yaml
   gtag_display:
     battery_voltage: !remove
   ```

4. Проверьте конфигурацию, запустите **Install → Manual download** и скачайте UF2.
   При первой сборке ESPHome загружает компоненты и инструменты из интернета.
5. Подключите плату к компьютеру, войдите в загрузчик двойным Reset и скопируйте
   UF2 на появившийся USB-диск. После перезапуска плата доступна по Bluetooth;
   USB в основной прошивке отключён.

Готовый файл конфигурации: [gtag-ble.yaml](../config/esphome/gtag-ble.yaml).
Пакет и внешний C++-компонент закреплены на одном теге `v0.8.0`.
Для обновления прошивки изменяйте тег пакета на опубликованную версию;
редактор экранов и выбор сущностей находятся в HA и не требуют пересборки.

Каждому экрану задавайте отдельное имя конфигурации ESPHome. HA различает
устройства по адресам Bluetooth. Имя BLE-рекламы остаётся **GTag Display**;
переименовать устройство для удобства можно в HA.

Настройки можно переопределить через substitutions:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `gtag_name` | `nrf-gtag-display` | Имя конфигурации ESPHome |
| `gtag_friendly_name` | `NRF GTag Display` | Отображаемое имя в ESPHome |
| `gtag_tx_power` | `"0"` | Мощность BLE: `"0"`, `"4"` или `"8"` dBm |
| `gtag_advertising_interval` | `1s` | Интервал BLE-рекламы |
| `gtag_battery_calibration` | `"1.0"` | Поправка напряжения, 0.8–1.2 |

По умолчанию включено измерение через **внешний делитель на P0.31**.
[Подключение аккумулятора и диагностика](battery.md).
Для диагностики можно добавить `logger: {level: INFO}`; USB-логирование
увеличивает потребление, поэтому для штатной работы оставляйте его выключенным.

## Готовая прошивка и ручная установка интеграции

В [GitHub Releases](https://github.com/lukdut/gtag-nrf-display/releases) публикуются:

- `gtag-display.uf2` — прошивка для nRF52840 Pro Micro / nice!nano с распиновкой
  из README и включённым измерением аккумулятора;
- `gtag-ha-integration.zip` — ручная установка: распакуйте в `/config/` HA
  с заменой файлов и перезапустите Home Assistant;
- `SHA256SUMS` — контрольные суммы файлов.

При ручной установке должен получиться
`/config/custom_components/gtag_ble_test/manifest.json`. Копируйте каталог
целиком, включая `fonts/`, `translations/` и `brand/`.

## Локальная разработка и выпуск версий

`config/esphome/nrf-gtag-display.yaml` использует те же настройки платы,
но загружает компонент из локальной папки `components/`. Команды сборки
приведены в [README](../README.md). Архив интеграции собирается командой
`python3 scripts/package.py`.

Для релиза обновляются версия в `manifest.json`, тег в
`packages/ble.yaml` и `gtag-ble.yaml`, инструкция и описание
`docs/releases/<версия>.md`. Workflow **Release** запускается тегом `v<версия>`:
сначала проверяет интеграцию и протокол, затем собирает публичную конфигурацию
ESPHome из GitHub и публикует UF2, ZIP и контрольные суммы.

Интеграция устанавливается через HACS, а компоненты прошивки — средствами
ESPHome. HACS не устанавливает ESPHome и не копирует конфигурацию прошивки.
Поддержка Zigbee и матрица проверок HA OS / HA Container описаны в
[плане развития](roadmap.md).
