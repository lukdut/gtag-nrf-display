# Установка GTag Display

## Текущее состояние

Интеграция 0.7.1 подготовлена для структуры HACS и проверена на Home Assistant
2026.9.2. GitHub-репозиторий пока не создан. До публикации доступна установка
из локального архива; путь установки и добавленное устройство затем сохранятся
при переходе на HACS.

HACS устанавливает компонент Home Assistant и его обновления. Прошивка
nRF52840 устанавливается отдельно. Для экранов подходит ранее проверенная
прошивка; для нового датчика аккумулятора нужны обновлённая прошивка и
[внешний делитель на P0.31](battery.md).

## Установка или обновление сейчас

1. Соберите архив командой `python3 scripts/package.py` из корня проекта.
   Результат: `dist/gtag-ha-integration.zip`.
2. Распакуйте его в `/config/` Home Assistant с заменой файлов. Должен получиться
   `/config/custom_components/gtag_ble_test/manifest.json`. Рядом нужны все
   Python-файлы, `services.yaml`, `fonts/`, `translations/` и `brand/`.
3. Перезапустите HA. Уже добавленное устройство удалять не нужно.
4. При первой установке добавьте обнаруженный **GTag Display** через
   **Настройки → Устройства и службы**. Нужен Bluetooth-адаптер или прокси,
   поддерживающий активные подключения.
5. Нажмите шестерёнку **Настроить / Configure** справа от записи GTag Display,
   выберите макет, сущности,
   проверьте предпросмотр и примените настройки.

Вместо архива можно скопировать каталог `custom_components/gtag_ble_test`
целиком в `/config/custom_components/`. В исходниках он теперь находится
в корне проекта; файлы прошивки остались в `config/esphome/`.

## Установка через HACS после публикации

HACS поддерживает публичные GitHub-репозитории. Для первой публикации достаточно
пользовательского репозитория; включение в общий каталог — отдельный последующий
шаг. [Общие требования](https://www.hacs.xyz/docs/publish/start/) и
[требования к интеграциям](https://www.hacs.xyz/docs/publish/integration/).

Когда публичный репозиторий будет создан:

1. В HACS откройте меню → **Пользовательские репозитории / Custom repositories**.
2. Вставьте URL репозитория, выберите тип **Интеграция / Integration**, добавьте.
3. Найдите **GTag Display** в HACS, скачайте и перезапустите HA.
4. Добавьте устройство и настройте экран через обычную страницу интеграций HA.

Для уже установленной вручную интеграции HACS должен использовать то же
техническое имя `gtag_ble_test`; домен сохранён для совместимости.
[Инструкция HACS по пользовательским репозиториям](https://www.hacs.xyz/docs/faq/custom_repositories/).

## Подготовка публикации

В репозитории уже есть нужная структура `custom_components/gtag_ble_test/`,
`hacs.json`, локальные изображения бренда и GitHub Actions с тестами.
В `hacs.json` минимальная версия HA установлена в 2026.9.2 — проверенную
версию окружения. Совместимость с более ранними версиями пока не проверялась.

После выбора настоящего адреса репозитория и GitHub-пользователя сопровождающего
выполните, заменив значения в примере:

```sh
python3 scripts/prepare_hacs.py OWNER/REPOSITORY --codeowner USERNAME
```

Скрипт локально добавляет в `manifest.json` реальные `documentation`,
`issue_tracker` и `codeowners`. Сейчас этих данных нет: адрес репозитория
и GitHub-имя ещё не определены. Заглушки под видом настоящих ссылок не используются.
Скрипт не создаёт репозиторий, не отправляет коммиты и не публикует релиз.

После этого нужно сохранить изменения, опубликовать проект на GitHub, добавить
описание и темы репозитория. Для обновлений удобно создавать GitHub Releases
с версией, совпадающей с `manifest.json`, например `0.7.1`. HACS скачает файлы
интеграции из `custom_components/`; архив из `scripts/package.py` предназначен
для ручной установки и не требует настройки `zip_release`.

До публикации и заполнения метаданных фактическая установка из HACS
не проверена. [Правила версий и релизов HACS](https://www.hacs.xyz/docs/publish/start/#versions).
