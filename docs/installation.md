# Установка GTag Display

Стабильный релиз — **0.9.0**, для Bluetooth и Zigbee2MQTT.
Репозиторий: [lukdut/gtag-nrf-display](https://github.com/lukdut/gtag-nrf-display).
Проверенные версии: **Home Assistant 2026.9.2**, **ESPHome Device Builder 2026.9.0**,
**Zigbee2MQTT 2.12.0**, **nRF Connect SDK 2.9.2**. Более новые версии
не считаются проверенными автоматически.

Для локальной версии после 0.9.0 доступен [мастер подготовки конфигурации в HA](firmware-wizard.md).

Для версии интеграции после 0.9.0 чистая установка ZIP в
**HA Container 2026.9.2 на Linux amd64 и arm64** проверена автоматически,
включая MQTT, макеты, мастер и перезапуск HA.
Радиоустройство в CI имитируется; установка через HACS и настоящий экран
проверяются отдельно. [Сценарий и результаты](container-verification.md).

## Подготовка экрана

Начните с [инструкции с фотографиями](display-preparation.md): разборка корпуса,
отклеивание платы, четыре разреза дорожек, пайка DIO/CLK/CS/RESET и обратная
сборка. Штатные питание LCD и тактирование DisplayCLK / S1 сохраняются.
Затем подключите nRF52840 и сверьте GPIO с конфигурацией прошивки.

## Интеграция через HACS

1. В HACS откройте меню → **Пользовательские репозитории / Custom repositories**.
2. Добавьте `https://github.com/lukdut/gtag-nrf-display`, тип **Integration**.
3. Найдите **GTag Display**, скачайте **v0.9.0** и перезапустите Home Assistant.
   Если версия ещё не появилась, выполните **Update information**.
4. Для Zigbee установите [внешний конвертер и добавьте экран](zigbee-home-assistant.md).
   В HA нужна штатная интеграция MQTT, подключённая к брокеру Zigbee2MQTT.
   Для Bluetooth нужен адаптер или прокси с поддержкой активных подключений.
5. Откройте **Настройки → Устройства и службы → Добавить интеграцию → GTag Display**
   (либо **Add entry**) и выберите способ связи. BLE-экран также может обнаружиться сам.
6. Нажмите шестерёнку **Настроить / Configure** справа от записи интеграции,
   выберите макет и сущности, проверьте предпросмотр и примените настройки.

HACS устанавливает интеграцию; прошивка собирается отдельно в ESPHome.
Пользовательский репозиторий HACS доступен без включения в общий каталог.
[Инструкция HACS](https://www.hacs.xyz/docs/faq/custom_repositories/).

## Обновление существующей установки

Обновите интеграцию до 0.9.0 и перезапустите HA. Для Zigbee замените также
`gtag-display.mjs` файлом из этого релиза и перезапустите Zigbee2MQTT.
Записи GTag, идентификаторы сущностей и сохранённые настройки удалять не нужно:
технический домен `gtag_ble_test` сохранён.

Перепрошивать все экраны одновременно не требуется. Новая интеграция и конвертер
согласовывают возможности с каждой платой. Прежние прошивки с протоколом кадров 1
без INFO работают в режиме **legacy**: RAW, без подтверждённой поддержки значка
устаревания. Точная версия такой прошивки неизвестна. Начальные тестовые проекты
без BEGIN/CRC сюда не относятся. [Совместимость](firmware-compatibility.md).

Для логотипа, полоски батареи, защиты от разряда и сообщения версии установите
прошивку 0.9.0 для своей платы. Сопряжение Zigbee при обычном обновлении того же
профиля сохраняется. При смене варианта с батареей на вариант без неё меняется
состав endpoints: выполните повторное Interview в Zigbee2MQTT и перезагрузите
запись GTag в HA. Подробности — в [настройке GPIO](pin-remapping.md).

## Сборка прошивки через ESPHome

В HA OS используйте приложение ESPHome Device Builder; при HA Container —
ESPHome в Docker или другую поддерживаемую установку на отдельном компьютере.
Интеграция не требует Supervisor. [Установка ESPHome](https://esphome.io/install/).
Полная сборка из YAML мастера в официальном ESPHome Container проверена на
**Linux amd64 и arm64** для Pro Micro / nice!nano с Zigbee и измерением батареи.
[Версии, отчёты и границы проверки](container-verification.md).

1. Создайте конфигурацию в **ESPHome Device Builder 2026.9.0**.
2. Скопируйте полный подходящий YAML:
   - [Pro Micro / nice!nano, Zigbee](../config/esphome/gtag-zigbee.yaml);
   - [Pro Micro / nice!nano, Bluetooth](../config/esphome/gtag-ble.yaml);
   - [Super52840, Zigbee без измерения батареи](../config/esphome/gtag-super52840-zigbee.yaml).
3. Задайте уникальное `gtag_name`, сверьте GPIO, загрузчик и наличие делителя.
   Все аппаратные поля и параметры батареи теперь обязательны. Для обновления
   старого YAML перенесите свои настройки в новый полный пример; одной замены
   тега недостаточно. `gtag_battery_calibration` заменён явным
   `gtag_display.battery_voltage.calibration`.
4. Если делителя нет, замените весь блок `battery_voltage` на `{enabled: false}`.
   Для Zigbee подключите также пакет `zigbee-no-battery.yaml` после основного.
   **Полный пример и оба варианта: [конфигурация устройства](device-configuration.md).**
5. Проверьте конфигурацию, запустите **Install → Manual download** и скачайте UF2.
   Пакет и C++-компонент загружаются из GitHub с одного тега `v0.9.0`.
6. Переведите плату двойным Reset в загрузчик и скопируйте UF2 на его USB-диск.
   После перезапуска диск исчезнет: USB в основной прошивке отключён.

Готовые Pro Micro UF2 используют внешний делитель 1 МОм / 1 МОм на P0.31
и пороги 3,306 / 4,19 / 3,45 В. Если делителя нет или распиновка другая,
соберите свой UF2. При включённом измерении низкое напряжение или ошибка АЦП
на старте блокируют радио. Проверка заряда повторяется раз в пять минут.
[Батарея и защита](device-configuration.md#разряд-и-восстановление).

Для каждого экрана используйте отдельный YAML. HA различает Zigbee-устройства
по IEEE, Bluetooth — по адресу. Содержимое экрана настраивается в HA и не требует
пересборки прошивки. [Макеты, округление и произвольные экраны](screens.md).

## Файлы релиза и ручная установка

В [релизе v0.9.0](https://github.com/lukdut/gtag-nrf-display/releases/tag/v0.9.0):

| Файл | Назначение |
|---|---|
| `gtag-zigbee.uf2` | Pro Micro / nice!nano, Zigbee, загрузчик S140 v6 |
| `gtag-display.uf2` | Та же плата, Bluetooth |
| `gtag-super52840-zigbee.uf2` | Super52840, S140 v7, свои GPIO, без АЦП |
| `gtag-*.yaml` | Публичные конфигурации ESPHome с закреплённым тегом |
| `*-esphome.zip` | Автономные исходники и локальный YAML для сборки |
| `gtag-display.mjs` | Внешний конвертер Zigbee2MQTT |
| `gtag-ha-integration.zip` | Ручная установка интеграции HA |
| `SHA256SUMS` | Контрольные суммы файлов |
| `LICENSE` | Лицензия MIT проекта; лицензия шрифта сохранена отдельно |

Для ручной установки распакуйте `gtag-ha-integration.zip` в `/config/` HA
с заменой файлов и перезапустите HA. Должен получиться
`/config/custom_components/gtag_ble_test/manifest.json`. Каталог устанавливается
целиком, включая `fonts/`, `translations/` и `brand/`.

## Локальная разработка и выпуск версий

`config/esphome/nrf-gtag-*.yaml` используют локальный `components/gtag_display`.
Команды сборки — в [README](../README.md). Архив интеграции собирается
`python3 scripts/package.py`.

При выпуске обновляются `manifest.json`, теги трёх публичных YAML и пакетов
`ble.yaml` / `zigbee.yaml`, инструкция и `docs/releases/<версия>.md`.
Для выпуска изменённой прошивки обновляется также `firmware_info::VERSION`;
при выпуске только интеграции версия уже прошитых устройств не меняется.

CI проверяет публичные YAML и полный пример документации с исходниками
кандидата ещё до публикации тега. Workflow **Release** по тегу `v<версия>`
повторяет тесты, собирает три публичные конфигурации уже из GitHub и публикует
UF2, YAML, исходники, конвертер, интеграцию и контрольные суммы. Стабильный
релиз не может содержать версию прошивки с суффиксом разработки.
Теги с суффиксом `-beta.*` создают предварительный выпуск, не заменяя Latest.
