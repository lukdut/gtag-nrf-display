# Полная конфигурация устройства в ESPHome Device Builder

Этот пример относится к текущим исходникам **после v0.9.0-beta.3**.
Опубликованные конфигурации `gtag-*.yaml` пока закреплены за beta.3:
в ней ещё нет защиты от разряда и обязательных параметров батареи.
До следующего релиза используйте локальные исходники, как описано ниже.

В HA нужен ESPHome Device Builder 2026.9.0. Параметры аппаратуры задаются
в YAML ESPHome и применяются после сборки и прошивки. Содержимое экрана
по-прежнему настраивается в интеграции GTag Display в HA.

1. Скопируйте содержимое `config/esphome/` из этой версии проекта в
   `/config/esphome/gtag/` на машине с Device Builder. Нужны каталоги
   `components/gtag_display` и `packages`.
   Вместо этого можно распаковать соответствующий `gtag-zigbee-esphome.zip`
   из той же сборки в этот каталог: он содержит все необходимые исходники.
2. Создайте в Device Builder файл `gtag-kitchen.yaml` следующего содержания.
   Это пример для **Pro Micro / Super Mini с загрузчиком nice!nano S140 6.x**,
   внешним делителем 1 МОм / 1 МОм и конденсатором 100 нФ.

```yaml
substitutions:
  gtag_name: gtag-kitchen
  gtag_friendly_name: "Экран кухни"

packages:
  gtag: !include gtag/packages/zigbee-base.yaml

external_components:
  - source:
      type: local
      path: gtag/components
    components: [gtag_display]

nrf52:
  board: adafruit_itsybitsy_nrf52840
  bootloader: adafruit_nrf52_sd140_v6
  dcdc: false
  framework:
    version: 2.9.2

gtag_display:
  dio_pin: P0.11
  clk_pin: P1.04
  cs_pin: P1.06
  reset_pin: P1.13
  battery_voltage:
    enabled: true
    pin: P0.31
    calibration: 1.0
    empty_voltage: 3.306V
    full_voltage: 4.19V
    recovery_voltage: 3.45V
    indicator: true
```

3. Соберите и скачайте UF2, переведите плату двойным Reset в загрузчик
   и скопируйте UF2 на его USB-диск.
4. Установите `zigbee2mqtt/gtag-display.mjs` из той же версии проекта
   в Zigbee2MQTT, сопрягите устройство и добавьте его в интеграцию GTag Display.
   Уже сопряжённое устройство после обычного обновления сохраняет сеть.

Для Bluetooth замените единственную строку пакета на
`gtag: !include gtag/packages/ble-base.yaml`. Аппаратные параметры остаются
такими же; конвертер Zigbee2MQTT в этом варианте не используется.
Для второго устройства задайте другое `gtag_name`.

## Обязательные параметры

Компонент требует все четыре GPIO и блок `battery_voltage` с явным `enabled`.
При `enabled: true` обязательны также `pin`, `calibration`, `empty_voltage`,
`full_voltage` и `recovery_voltage`. Скрытых значений YAML для этих полей нет:
ошибка будет показана до сборки. `indicator` и параметры работы радио остаются
необязательными. Профиль платы/загрузчика указан явно в полном примере;
его нужно сверять с конкретной платой.

| Поле батареи | Значение |
|---|---|
| `enabled` | Есть ли подключённый делитель и измерение |
| `pin` | Аналоговый GPIO, подключённый к середине делителя |
| `calibration` | Поправка по мультиметру: `Uмультиметра / Uдатчика`, при исходном 1.0 |
| `empty_voltage` | 0% шкалы; ниже этого напряжения отключается связь |
| `full_voltage` | 100% шкалы; пример: 4,19 В и выше |
| `recovery_voltage` | Порог разрешения радио после каждого включения и после разряда |
| `indicator` | Показывать нижнюю полоску; по умолчанию `true` |

Требуется `empty_voltage < recovery_voltage <= full_voltage` с точностью
до милливольта. Пороги относятся к напряжению аккумулятора после пересчёта
делителя и калибровки. Соотношение резисторов фиксировано: 1:1.

Если делителя нет, замените **весь** блок батареи на:

```yaml
gtag_display:
  # Четыре GPIO экрана остаются обязательными.
  battery_voltage:
    enabled: false
```

В Zigbee дополнительно подключите пакет **после основного**:

```yaml
packages:
  gtag: !include gtag/packages/zigbee-base.yaml
  no_battery: !include gtag/packages/zigbee-no-battery.yaml
```

Этот пакет также убирает Zigbee-датчик и выбирает модель без батареи.
Готовый пример другой платы —
[`nrf-gtag-super52840-zigbee.yaml`](../config/esphome/nrf-gtag-super52840-zigbee.yaml).
Её загрузчик и GPIO отличаются от приведённого выше примера.

## Разряд и восстановление

При напряжении **ниже `empty_voltage`** на очередном измерении прошивка
перезапускает МК. После перезапуска радио не запускается, экран показывает
**Low battery**, а процессор использует System ON idle. Проверка батареи
происходит через секунду после включения и затем **раз в пять минут**;
обнаружение разряда и заряда может занять до пяти минут.

При достижении **`recovery_voltage`** запускается выбранное радио, возвращается
стартовый рисунок и возобновляется получение данных. При `boot_test_pattern: none`
предупреждение заменяется белым экраном до следующего кадра. Настройки Zigbee
и сопряжение сохраняются. Порог восстановления применяется при **каждом**
включении: например, при 3,40 В плата ещё ждёт зарядки, хотя рабочий порог
отключения равен 3,306 В. Этот запас уменьшает риск повторных включений
из-за повышения напряжения после снятия нагрузки.

При ошибке АЦП на старте показывается **Battery error**, радио также ждёт
успешного измерения. Ошибка АЦП во время обычной работы не считается нулевым
напряжением и сама по себе не вызывает перезапуск.

System OFF не используется: RTC nRF52840 не может разбудить его для замера
([пояснение Nordic](https://devzone.nordicsemi.com/f/nordic-q-a/19276/deep-sleep-with-rtc-wakeup/74706)).
Связь в режиме защиты отсутствует, но МК, штатная схема экрана и делитель
остаются подключены к аккумулятору. Поэтому программное отключение радио
**не заменяет аппаратную защиту аккумулятора от глубокого разряда**.
Потребление нового режима нужно измерить на плате.

## Проверка этой реализации

18 сентября 2026 года прошли 45 тестов протокола/драйвера и 8 проверок
конфигурации, включая полный пример выше. Собраны Zigbee и Bluetooth
для Pro Micro, а также Zigbee без батареи для Super52840. Тесты моделируют
низкий заряд на старте, разряд во время работы, ошибку АЦП, гистерезис
и запуск радио после зарядки. В готовом Zigbee-бинарнике проверен вызов
обёртки, блокирующей `zigbee_enable()` до разрешения батарейной проверки.

В 20:12 основная Super Mini / nice!nano прошита Zigbee-вариантом. Сохранённое
сопряжение восстановилось; Zigbee2MQTT подтвердил новый кадр `displayed`,
счётчик после перезапуска — 2. Пользователь проверил отключение при снижении
напряжения и автоматическое восстановление при его повышении на физической
плате с лабораторным блоком питания и подтвердил корректную работу.
Точные измеренные пороги и ток режима защиты не зафиксированы.
