# D1 mini (ESP8266): Wi-Fi и питание от USB

Профиль для D1 mini на ESP8266 с 4 МБ flash. Экран подключается к Home
Assistant через ESPHome Native API, как ESP32-C3. Поддерживаются все макеты,
передача RAW/RLE, четыре простых шаблона на устройстве, подтверждение записи
кадра и значок устаревших данных. BLE, Zigbee и измерение аккумулятора в этом
профиле не используются.

Поддержка добавлена в **1.3.0**. Публичный YAML и мастер загружают исходники
с GitHub-тега `v1.3.0`; также доступен автономный архив ESPHome.

## Подключение

Сначала выполните [подготовку ценника](display-preparation.md).

| Сигнал LCD | Надпись на D1 mini | GPIO в YAML |
|---|---|---|
| DIO | D2 | GPIO4 |
| CLK | D1 | GPIO5 |
| CS | D6 | GPIO12 |
| RESET | D5 | GPIO14 |
| GND | G | GND |

USB питает D1 mini. Сохраните штатное питание LCD и тактирование
**DisplayCLK/S1**: прошивка этот сигнал не генерирует. Земля должна быть общей.
На сигнальные выводы LCD нельзя подавать USB 5 В.

Обозначения D1/D2 на плате отличаются от номеров GPIO. Мастер принимает
`GPIO4`, `GPIO5`, `GPIO12`, `GPIO13`, `GPIO14`, `GPIO16`; GPIO0/2/15 оставлены
для загрузки, GPIO1/3 — для UART, GPIO6–11 — для flash. По умолчанию D0/GPIO16
и D7/GPIO13 свободны. [Распиновка производителя](https://docs.wemos.cc/en/latest/d1/d1_mini.html).

## Сборка и установка

Нужен ESPHome **2026.9.0 или новее**; проверки выполнены на 2026.9.0.

Выберите **D1 mini ESP8266 (USB, Wi-Fi)** в
**GTag Display → Подготовить прошивку**, способ связи **Wi-Fi**. Проверьте
GPIO, введите параметры Wi-Fi, ключ API и пароль OTA, скачайте YAML.

Для текущих локальных исходников:

```sh
python3 scripts/package_wifi.py --board d1_mini
```

Распакуйте `dist/gtag-d1-mini-wifi-esphome.zip`, скопируйте
`secrets.example.yaml` в `secrets.yaml` и заполните его. Ключ API — случайные
32 байта в Base64; его можно создать командой `openssl rand -base64 32`.
Задайте уникальное имя устройства через `substitutions.gtag_name`.

```sh
esphome run esp8266-gtag-display.yaml
```

Первую установку выполните по USB. Дальнейшие обновления используют ESPHome
OTA. Добавьте устройство в стандартную интеграцию **ESPHome** с ключом API,
затем в **GTag Display → Wi-Fi (ESPHome)**. Настройка макетов общая для всех
плат. Секреты хранятся в вашей конфигурации; готовый универсальный BIN
для публикации не создаётся.

При сборке непосредственно из репозитория используйте
[`config/esphome/esp8266-gtag-display.yaml`](../config/esphome/esp8266-gtag-display.yaml)
и свой `config/esphome/secrets.yaml`.

### Через Home Assistant

Архив `gtag-ha-integration.zip` обновляет интеграцию и мастер выбора платы.
Распакуйте его в `/config/` с заменой `custom_components/gtag_ble_test` и
перезапустите HA. Прошивку платы собирает и устанавливает отдельный
**ESPHome Device Builder**; само обновление интеграции плату не прошивает.

Для сборки из автономного архива распакуйте `gtag-d1-mini-wifi-esphome.zip` в каталог
конфигураций ESPHome (обычно `/config/esphome/`), сохранив `packages/` и
`components/`. Добавьте необходимые значения из `secrets.example.yaml` в
существующий `secrets.yaml` или создайте его, если файла ещё нет. Не заменяйте
секреты других устройств. Откройте `esp8266-gtag-display.yaml` в Device
Builder, проверьте имя и GPIO, затем выберите **Install**. Первую запись
выполните по USB; USB может быть подключён к серверу ESPHome либо к компьютеру
с браузером, поддерживающим Web Serial. После первой установки доступно OTA.
[Варианты установки ESPHome](https://esphome.io/install/).

Уже прошитую плату добавьте через **Настройки → Устройства и службы →
Добавить интеграцию → ESPHome**: укажите IP, порт `6053` и ключ шифрования API
из конфигурации прошивки. Затем добавьте **GTag Display → Wi-Fi (ESPHome)**,
выберите это устройство и настройте макет.

## Память и проверка на плате

Драйвер хранит два буфера по 4096 байтов; RAW декодируется сразу в буфер
следующего кадра. Сжатые пакеты используют временный буфер своего размера.
Шрифты и заставка хранятся во flash и читаются через `PROGMEM`. Повреждённый
пакет не заменяет последний проверенный кадр. LCD записывается порциями по
64 байта; рендеринг шаблонов передаёт управление Wi-Fi между операциями.

По умолчанию доступны два подключения API: HA и один клиент логов ESPHome.
Дополнительные датчики и другие компоненты увеличивают расход RAM.
У ESP8266 небольшой запас памяти; при расширении YAML проверяйте свободную
кучу и наибольший свободный блок во время передачи полного изображения.
[Ограничения API ESPHome](https://esphome.io/components/api/).

2 октября 2026 года на физической ESP8266EX с 4 МБ flash и прошивкой
`1.3.0-dev.1` проверены USB-запись,
подключение к Wi-Fi, зашифрованный API, полный RAW-кадр, RLE и четыре шаблона,
включая кириллицу. Контрольные суммы совпали с эталонами, кадр с неверной CRC
отклонён. Пользователь подтвердил видимое изображение на подключённом LCD.
Также прошли RAW с двумя клиентами API и зашифрованное OTA при этих двух
подключениях, с повторным подключением API и выводом шаблона после перезапуска.

Отдельно остаются проверки длительной работы, свободной кучи, потери Wi-Fi,
значка устаревших данных и полного сценария через установленный HA.
Размеры сборки и команды приведены в [проверках проекта](testing.md).
