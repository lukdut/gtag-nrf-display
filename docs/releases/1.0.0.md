# GTag Display 1.0.0

Экран настраивается через Home Assistant: подготовка прошивки, выбор содержимого,
перенос макетов и диагностика собраны в одной интеграции.

## Новое

- **Мастер конфигурации ESPHome** создаёт полный YAML: плата, транспорт,
  GPIO, наличие измерения аккумулятора, калибровка и пороги защиты.
  Ссылка скачивания работает до и после завершения мастера.
- **Экспорт и импорт макетов**: файл JSON, сопоставление сущностей и предпросмотр
  перед применением. Поддерживаются стандартные макеты и собственные шаблоны.
- **Диагностика устройства**: версия прошивки, функции, кодеки, последние
  успешные обновления и причина ошибки. «Проверить связь» получает свежий ответ
  платы, не меняя изображение и таймер актуальности. Exposes Zigbee2MQTT сокращены,
  низкоуровневые команды MQTT сохранены.
- **Погода и почасовой прогноз**: текущие условия, температура, влажность и шесть
  ближайших записей прогноза из `weather.get_forecasts`.
- **Значение и график**: числовой датчик с историей Recorder за 1–168 часов,
  автоматическая шкала, округление и пропуски недоступных данных.
- Инструкция подготовки ценника с фотографиями, установка HA Container через
  HACS и сборка в ESPHome со скриншотами. README показывает исходный ценник,
  готовый экран и последовательность установки.

## Исправления

- Команды MQTT ожидают завершения подписки: быстрый ответ при запуске HA
  больше не теряется.
- Диагностические значения переводятся на язык профиля пользователя,
  независимо от языка сервера HA.

## Обновление с 0.9.0

1. Обновите GTag Display через HACS или распакуйте `gtag-ha-integration.zip`
   в `/config/` с заменой файлов. Перезапустите HA и обновите страницу браузера.
2. Для Zigbee замените `gtag-display.mjs` в Zigbee2MQTT файлом из этого выпуска
   и перезапустите Zigbee2MQTT.
3. В настройках записи GTag доступны новые макеты, импорт/экспорт и диагностика.
   Мастер YAML находится в **Добавить запись → Подготовить прошивку**.

**Перепрошивка и пересопряжение работающих экранов не требуются.** Прошивка
сохраняет версию **0.9.0**. Мастер закрепляет YAML на проверенном теге v0.9.0;
публичные YAML выпуска используют v1.0.0 с тем же исходным кодом прошивки.
Домен `gtag_ble_test`, идентификаторы сущностей, макеты и аппаратные настройки
сохранены. Прежние прошивки продолжают использовать согласованные возможности
или режим legacy. Новые макеты требуют интеграции 1.0.0, но используют прежний
протокол кадров. Формат экспорта остаётся v1; старые файлы импортируются.

## Условия и проверка

Основной профиль — Pro Micro / nice!nano через **Zigbee2MQTT**. Super52840
и Bluetooth остаются дополнительными вариантами. Проверенные версии:
**HA 2026.9.2, ESPHome 2026.9.0, Zigbee2MQTT 2.12.0, NCS 2.9.2**.

Для прогноза нужна погодная сущность с почасовым прогнозом. Для графика нужен
Recorder и записываемая числовая сущность; без истории текущее значение остаётся,
а график показывает прочерк. Запрос ограничен 10 001 изменением плюс начальное
состояние: при достижении лимита период помечается `…`, график неполный.
Данные с разными единицами на одной шкале не смешиваются.

Чистая установка HA Container и полная нативная сборка ESPHome ранее проверены
на **amd64 и arm64**. На amd64 дополнительно проверены HACS, работа физического
экрана, перезапуск и скачивание UF2 через браузер Device Builder.
[Результаты и границы проверки](../container-verification.md).
Новые макеты проверяются с настоящими API Weather/Recorder, импортом, обновлением
по времени и перезапуском интеграции; предпросмотры включены в [инструкцию](../screens.md).

Физическая проверка двух новых макетов пользователем пока не зафиксирована.
Запись именно ARM-сборки на плату отдельно не выполнялась; в проверенном прогоне
UF2 из amd64 и arm64 совпали побайтно.

Выпуск содержит ZIP интеграции, конвертер Zigbee2MQTT, готовые UF2 и исходники
ESPHome для трёх профилей, публичные YAML, MIT LICENSE и SHA256SUMS.
Перед записью готового UF2 сверьте GPIO, профиль загрузчика и настройки батареи.
