# Проверки GTag Display

[Описание проекта](../README.md) · [История версий](../CHANGELOG.md) ·
[Локальная сборка](development.md)

Программные тесты проверяют данные, команды и поведение компонентов.
Они не заменяют измерение тока, электрических сигналов и работу с физическим
радиоканалом. Результаты ниже относятся к указанной сборке и окружению.

## Сборка 1.2.0-dev.2

| Проверка | Результат |
|---|---|
| Home Assistant 2026.9.2, Python 3.14 | 334 теста пройдены |
| Нативные драйверы, транспорт, шрифты и упаковка | 67 тестов пройдены |
| Конвертер Zigbee2MQTT и C++-приёмник | 38 тестов пройдены |
| Переводы и отображение ссылок в HA | 18 тестов пройдены |
| Pro Micro BLE, Pro Micro Zigbee, Super52840 Zigbee | Три UF2 собраны и проверены |

Прошивки собраны на ESPHome 2026.9.0 и nRF Connect SDK 2.9.2.
Сборка dev.2 работает на nice!nano с Zigbee, стандартными GPIO и без измерения
напряжения. Чтение flash подтвердило все 2097 блоков приложения; SoftDevice
S140 6.1.1 сохранён. Это проверка данного профиля, а не всех вариантов плат.

Тесты шаблонов сравнивают все 4096 байтов изображения между Pillow, Python
и C++. Проверяются дни недели, цифры, кириллица, метрики и кернинг шрифтов,
отказ от передачи строк при несовпадении пикселей, ошибки пакетов и CRC,
а также переход на RAW/RLE после отката прошивки.

| Профиль | Flash приложения | RAM | Конец блоков UF2 |
|---|---|---|---|
| Pro Micro Zigbee | 548 364 Б | 65 800 Б | `0xABF00` |
| Pro Micro Bluetooth | 434 208 Б | 40 496 Б | `0x90100` |
| Super52840 Zigbee | 536 632 Б | 64 944 Б | `0xAA100` |

Адреса UF2 ограничены `0xAD000`, независимо от большего раздела в отчёте
линкера. Начало приложения — `0x26000` для Pro Micro и `0x27000` для
Super52840. Блоки загрузчика в пакеты не включаются.

## Запуск тестов

Команды выполняются из корня репозитория. Нативные тесты и тесты HA запускайте
отдельно: первые используют заглушки модулей Home Assistant.

### Нативные драйверы и транспорт

Нужны Python 3.11+ и g++; установка HA и SDK не требуется.

```sh
python3 -m unittest discover -s tests -v
```

Тесты компилируют настоящий C++-драйвер с моделями GPIO, BLE и планировщика,
подают пакеты Python-отправителя и сравнивают слова LCD с исходной записью
ESP32. Проверяются таймеры, реклама BLE, повреждённые кадры, повторы,
восстановление передачи, аккумулятор, Wi-Fi и границы UF2.

### Zigbee2MQTT

Нужны Node.js 24, Python и g++. Зависимости закреплены для Zigbee2MQTT 2.12.0.

```sh
npm ci --prefix tests/zigbee --ignore-scripts --no-audit --no-fund
npm test --prefix tests/zigbee
```

Внешний конвертер связан через настоящий ZCL-кодек с C++-драйвером.
Проверяются упаковка пикселей `row-lsb`, CRC, потеря ответов, перезапуск,
согласование кодеков и подтверждение записи LCD. Проверка обработчика
zigbee-herdsman выявляет ошибки описания пользовательского кластера.

### Home Assistant

Используйте отдельное окружение Python 3.14:

```sh
python3.14 -m venv /tmp/gtag-ha-tests
/tmp/gtag-ha-tests/bin/pip install -r tests/requirements-ha.txt
/tmp/gtag-ha-tests/bin/python -m pytest tests/ha
```

Используются настоящие шаблоны, реестры, действия, хранилище, платформы
сущностей и диалоги настройки HA. Физическая доставка заменена моделью.
Покрыты рендеринг, обновления, очередь, ограничение частоты, сохранение
настроек и предпросмотра, импорт/экспорт и ошибки связи.

### Интерфейс

Переводы проходят ICU-форматирование, Markdown и фильтрацию HTML
в порядке, используемом интерфейсом HA. Нужен Node.js 24.

```sh
npm ci --prefix tests/frontend --ignore-scripts --no-audit --no-fund
npm test --prefix tests/frontend
```

## Измерения на устройствах

- Для BLE-сборки без контроля аккумулятора измерено около **50 мкА** в
  ожидании. Это не оценка среднего тока при обновлениях экрана и не результат
  для новых Zigbee-сборок. Делитель батареи добавляет до 2,1 мкА.
- Для `dev.1` один и тот же кадр с CRC `f0154bfe` передан через Zigbee:
  RLE — **1390 байтов, 11,777 с**; шаблон — **80 байтов, 2,023 с**.
  Полное время HA — 13,82 и 6,43 с соответственно, без повторов.
  Это сравнение передачи конкретного кадра, а не измерение расхода батареи.
- Снижение среднего тока от оптимизаций Zigbee и рендеринга на устройстве
  требует отдельного измерения.
