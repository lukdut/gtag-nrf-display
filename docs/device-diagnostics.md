# Диагностика устройства

Добавлена в локальную версию после 0.9.0. Обновите интеграцию HA и
[`gtag-display.mjs`](../zigbee2mqtt/gtag-display.mjs) в Zigbee2MQTT из одного
комплекта. Перезапустите HA и Zigbee2MQTT. Перепрошивка и пересопряжение
работающих плат с протоколом кадров v1 не нужны.

## Где искать

**Настройки → Устройства и службы → GTag Display → шестерёнка нужной записи →
Диагностика устройства**.

На одной странице собраны:

- способ подключения, версия прошивки и поддерживаемые функции;
- доступные кодеки и напряжение аккумулятора, если оно измеряется;
- время последней успешной передачи изображения и последнего подтверждения данных;
- состояние передачи, актуальность данных и ошибка обновления;
- результат последней проверки связи, её время, длительность и объяснение ошибки.

Для старой прошивки без INFO показывается «Старая прошивка (не сообщает версию)».
Её возможности считаются неизвестными; отправка использует консервативный RAW.
До первого ответа версия также может быть неизвестна — нажмите «Проверить связь».

Время успешного обновления сохраняется вместе с настройками после короткой
задержки до 30 секунд и при штатной выгрузке. После перезапуска HA это время
остаётся историей передачи; текущая актуальность требует нового подтверждения.

## Проверить связь

Выберите действие **Проверить связь** и нажмите **Submit / Подтвердить**.
Мастер показывает ожидание, затем возвращает результат на этой же странице.
Кнопка **Проверить связь** также есть на странице устройства; её результат
показывает датчик **Проверка связи** в разделе диагностики.

Проверка обращается к самой плате, обычно занимает несколько секунд, максимум
около минуты. Через Zigbee запрашивается INFO по существующему кластеру
`gtagFrame` (`0xFC11`) на найденном эндпоинте кадров. В ответе MQTT проверяется
уникальный ID запроса: сохранённые сообщения и ответы другой платы не подходят.
Через Bluetooth читается INFO; для старой прошивки после обновления кеша GATT
читается STATUS. Ошибка или таймаут не превращаются в успешный результат legacy.

Изображение, время его последней передачи и срок актуальности проверка не меняет.
Даже после ответа платы старые данные могут оставаться устаревшими; для их
обновления служит **Refresh display / Обновить экран**.
Результат проверки описывает момент запроса, а не постоянную доступность.
Фоновых опросов эта функция не добавляет.

Если устройство занято передачей кадра или чтением батареи, повторите запрос
после завершения операции. Проверки двух разных экранов независимы.

| Результат | Что проверить |
|---|---|
| MQTT отключён | Интеграцию MQTT в HA и брокер |
| Zigbee2MQTT не работает | Приложение Zigbee2MQTT |
| Устройство отсутствует | Сопряжение и базовый топик MQTT |
| Нужно обновить конвертер | Заменить `gtag-display.mjs` из текущего комплекта |
| Ответ не получен | Питание, радиосвязь, для Zigbee также конвертер |
| Несовместимая прошивка | Плата ответила, но интеграция не поддерживает её формат |
| Некорректный ответ | Версии прошивки и конвертера; технические подробности ниже |

Плата с активной защитой от разряда выключает радио. Проверка не может отличить
её от выключенного устройства или потери радиосвязи; после зарядки она вернётся
в сеть по алгоритму [защиты батареи](battery.md).

«Обновить сведения» перечитывает состояние интеграции без запроса к плате.
Успешная проверка не скрывает последнюю ошибку передачи изображения.

## Автоматизации

Действие `gtag_ble_test.check_connection` принимает выбранное устройство и
поддерживает ответ. Например, в последовательности автоматизации:

```yaml
- action: gtag_ble_test.check_connection
  data:
    device_id: ВАШ_ID_УСТРОЙСТВА_HA
  response_variable: gtag_check
- if: "{{ gtag_check.status == 'error' }}"
  then:
    - action: persistent_notification.create
      data:
        title: GTag Display
        message: "Проверка связи: {{ gtag_check.error_code }}"
```

Ответ содержит `status` (`ok` / `error`), `checked_at`, `duration_seconds`,
`error_code`, `error_detail`, версию и возможности прошивки, сведения об
обновлении изображения. Эти же данные доступны в атрибутах датчика
**Проверка связи**. Тексты в мастере и состояния датчика переведены на русский
и английский; коды в автоматизациях остаются стабильными.

## Exposes Zigbee2MQTT

В интерфейсе оставлены версия, функции и кодеки, напряжение при наличии АЦП,
тестовая картинка, статус/ошибка/длительность передачи, признак устаревания,
проверка связи и её результат/ошибка/время.

Служебные CRC, номера кадров, маски возможностей, поля подтверждения
актуальности, счётчик отрисовок, выбор аппаратного рисунка и отладка сна
убраны из Exposes. `frame_request_id` оставлен как маркер совместимости:
выпущенные интеграции HA используют его при обнаружении устройства.

Все прежние MQTT-команды и поля ответов сохранены, в том числе `frame`,
`frame_freshness`, `display_pattern_3`, `firmware_capabilities` и
`power_diagnostics`. Последняя команда по-прежнему требует специальной
прошивки с отладкой питания. Их отсутствие в Exposes не меняет MQTT API.

Для проверки через MQTT отправьте без retain:

```json
{"check_connection": "check"}
```

в `<base_topic>/<IEEE>/set`. Для корреляции своего запроса используйте
`{"check_connection":{"request_id":"my-check-1"}}`. Ответ содержит
`connection_request_id`, `connection_status` (`checking` / `ok` / `error`),
`connection_error_code`, `connection_error`, `connection_checked_at` и
`connection_duration_ms`. Успешный ответ также содержит свежие возможности.

Проверено автоматически на HA 2026.9.2 и библиотеках Zigbee2MQTT 2.12.0:
оба транспорта, legacy, ошибки и повторная проверка, два устройства,
неизменность кадра и его актуальности, реальный мастер HA и переводы.
После установки обновления пользователь подтвердил результат и готовность к коммиту.
