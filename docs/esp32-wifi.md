# ESP32-C3 Super Mini: Wi-Fi и питание от USB

Вариант для постоянно включённого экрана с питанием ESP32 от USB. Макеты,
предпросмотр, погода, графики, экспорт и импорт настраиваются в той же
интеграции GTag Display. Связь использует штатный API ESPHome; MQTT и
Bluetooth не требуются. Первая установка — через USB, следующие — через OTA.

**Статус:** предварительный выпуск **1.1.0-beta.1**. Установите эту версию
интеграции через HACS, включив показ предварительных выпусков, и перезапустите HA.
Проверка на физическом ESP32-C3 с экраном и лентой пока не выполнена.
Стабильная версия 1.0.1 поддерживает nRF52840 и не содержит профиля Wi-Fi.

## 1. Подключение

Подготовьте штатную плату по [инструкции с фотографиями](display-preparation.md).
Меняется плата управления и назначение GPIO:

| Экран G-Tag | ESP32-C3 Super Mini |
|---|---|
| DIO | GPIO0 |
| CLK передачи данных | GPIO1 |
| CS | GPIO3 |
| RESET | GPIO4 |
| GND | GND |

Сохраните питание штатной платы экрана и генерацию DisplayCLK/S1. Прошивка
этот сигнал не генерирует. USB питает ESP32; питание экрана подключается
отдельно согласно его штатной схеме. USB 5 В нельзя подавать на сигнальные
линии или непосредственно на LCD.

GPIO18/19 оставлены для встроенного USB, GPIO2/8/9 не используются из-за
их роли при загрузке. GPIO5 свободен для ленты. GPIO можно менять в YAML;
мастер предлагает выводы типовой ESP32-C3 Super Mini. Сверьте маркировку
своей платы. Измерение батареи и глубокий сон в этом профиле выключены.

## 2. Создание YAML

В HA откройте **Настройки → Устройства и службы → Добавить интеграцию →
GTag Display → Подготовить прошивку**. Выберите **ESP32-C3 Super Mini** и
**Wi-Fi**, укажите GPIO, затем SSID и пароль сети 2,4 ГГц.

Мастер создаёт ключ шифрования API и пароль OTA. Скачанный YAML содержит
эти данные и пароль Wi-Fi. При желании перенесите их в `secrets.yaml`.

Полный пример для ручного создания:

```yaml
substitutions:
  gtag_name: gtag-kitchen
  gtag_friendly_name: Экран кухни

packages:
  gtag: github://lukdut/gtag-nrf-display/config/esphome/packages/wifi.yaml@v1.1.0-beta.1

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password

api:
  encryption:
    key: !secret gtag_api_key

ota:
  - platform: esphome
    password: !secret gtag_ota_password

gtag_display:
  dio_pin: GPIO0
  clk_pin: GPIO1
  cs_pin: GPIO3
  reset_pin: GPIO4
  battery_voltage:
    enabled: false
```

Для ручного примера добавьте эти значения в `secrets.yaml`. Ключ API —
случайные 32 байта в base64, например результат `openssl rand -base64 32`.
Для каждого устройства задайте своё имя `gtag_name` и свои ключи.

Для **локальной разработки без GitHub-пакета** используйте
[esp32-gtag-display.yaml](../config/esphome/esp32-gtag-display.yaml) вместе
с каталогами `packages/` и `components/` из `config/esphome` и собственным
`secrets.yaml`. Сборка:

```sh
esphome compile config/esphome/esp32-gtag-display.yaml
```

Также в [релизе](https://github.com/lukdut/gtag-nrf-display/releases/tag/v1.1.0-beta.1)
есть автономный архив `gtag-esp32-c3-wifi-esphome.zip` с исходниками и пустым
`secrets.example.yaml`. Готового BIN для ESP32 нет: сборка содержит ваши
данные Wi-Fi, ключ API, пароль OTA, GPIO и дополнительные компоненты.

## 3. Первая прошивка и добавление в HA

1. Создайте устройство в ESPHome Device Builder 2026.9.0 и вставьте YAML.
2. Подключите ESP32-C3 по USB. Используйте установку ESPHome через USB
   с выбором компьютера/порта либо CLI `esphome run device.yaml`.
   Для браузерной установки нужен поддерживаемый браузер и HTTPS/localhost.
   Эта плата прошивается BIN; USB-диска для копирования UF2 у неё нет.
3. Если порт загрузчика не появился: удерживайте BOOT, нажмите и отпустите
   RESET, затем отпустите BOOT. После записи при необходимости нажмите RESET.
4. Добавьте устройство в обычную интеграцию **ESPHome** в HA: через обнаружение
   или по IP. При запросе введите ключ `api.encryption.key` из YAML.
5. Откройте **GTag Display → Wi-Fi (ESPHome)** и выберите устройство.
   В списке отображаются платы с доступными действиями GTag API.
6. Настройте содержимое через [макеты GTag Display](screens.md).

Кадры, версия прошивки и диагностика используют существующее соединение
ESPHome. Разрешение устройству выполнять действия HA не требуется:
команды передаются из HA на плату.

## 4. Обновления OTA

После первой USB-прошивки используйте **Install → Wirelessly** в ESPHome
или `esphome run device.yaml --device gtag-kitchen.local`.
Используются штатные OTA и safe mode ESPHome. Сохраняйте пароль OTA и свой YAML:
прошивка собирается с GPIO и дополнительными компонентами этого устройства.
Обновление интеграции через HACS и прошивки через ESPHome — отдельные операции.

## 5. Адресная лента и другие компоненты

Допишите в тот же YAML, например для WS2812:

```yaml
light:
  - platform: esp32_rmt_led_strip
    id: display_backlight
    name: Подсветка экрана
    pin: GPIO5
    num_leds: 30
    chipset: WS2812
    channel_colors: GRB
    effects:
      - addressable_rainbow:
      - addressable_scan:
```

Лента появится светильником через интеграцию ESPHome. Её цвет, яркость,
эффекты и автоматизации не зависят от интеграции GTag. Питание подбирается
по напряжению и току ленты; GPIO передаёт данные, питать от него ленту нельзя.
Земли ленты и ESP32 должны быть общими.

Можно добавлять датчики, кнопки, I²C, SPI, собственные API-действия и другие
компоненты ESPHome. Не занимайте GPIO экрана повторно. Компонент передаёт до
64 байт LCD за вызов `loop`, оставляя время другим компонентам.
Изменение макета в HA не требует перепрошивки; добавление ленты или смена
GPIO требуют пересборки и OTA.

## Передача и диагностика

HA запрашивает возможности прошивки, выбирает RAW или WHITE_RLE_V1 и передаёт
кадр через `gtag_frame`. Плата проверяет формат, декодирование и CRC32,
затем записывает LCD. Только после записи всех 4096 байт HA получает
подтверждение и обновляет предпросмотр. Некорректный кадр не заменяет предыдущий.

`gtag_confirm` продлевает актуальность неизменившегося изображения. При потере
связи появляется инвертированный значок; подтверждение или новый кадр убирают
его. Перезапуск платы сбрасывает подтверждение: HA обнаруживает это и при
следующем обновлении отправляет полный кадр. **Проверить связь** запрашивает
версию прошивки без изменения картинки и срока актуальности.

Автоматические проверки: `tests/ha/test_wifi.py`, `tests/test_wifi_driver.py`,
`tests/esphome/test_wifi_config.py`. Они не заменяют физическую проверку
сигналов, изображения, OTA и эффектов ленты.
