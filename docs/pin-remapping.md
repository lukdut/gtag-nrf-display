# Переназначение GPIO и вторая плата

В 0.9.0-beta.3 выводы экрана и измерения аккумулятора настраиваются в YAML
ESPHome. Настройка одинакова для Bluetooth и Zigbee. Она применяется при
сборке прошивки: редактор макета в HA управляет содержимым экрана.

## Настройка

В стабильной 0.9.0 GPIO и настройки батареи обязательны.
[Полный YAML для Device Builder](device-configuration.md).

Добавьте в конфигурацию устройства блок `gtag_display` или дополните имеющийся:

```yaml
gtag_display:
  dio_pin: P0.11
  clk_pin: P1.04
  cs_pin: P1.06
  reset_pin: P1.13
  battery_voltage:
    enabled: true
    calibration: 1.0
    empty_voltage: 3.306V
    full_voltage: 4.19V
    recovery_voltage: 3.45V
    pin: P0.31
```

Это прежняя стандартная распиновка, теперь указанная явно. Для другой платы замените значения на её
свободные физические GPIO. Обозначения относятся к самому nRF52840, а не к
номерам D0/D1 на плате. Допустимы строки `P0.00`…`P0.31`, `P1.00`…`P1.15`
и целые номера: `P1.04` соответствует 36. Выводы `P0.00`/`P0.01` заняты
кварцем 32 кГц в используемом профиле; `P0.09`/`P0.10` зарезервированы под NFC,
`P0.18` — под аппаратный Reset. Их выбор отклоняется.

Пример другой разводки **для платы, на которой эти выводы доступны и свободны**:

```yaml
gtag_display:
  dio_pin: P0.06
  clk_pin: P0.08
  cs_pin: P0.15
  reset_pin: P0.17
  battery_voltage:
    enabled: true
    calibration: 1.0
    empty_voltage: 3.306V
    full_voltage: 4.19V
    recovery_voltage: 3.45V
    pin: P0.04
```

Нельзя назначать один GPIO двум сигналам, использовать линию LCD как вход
батареи или делить GPIO с другим компонентом ESPHome. Проверки выполняются
до сборки. Инверсия, подтяжки и произвольные режимы GPIO для этих полей
не поддерживаются: электрический режим задаёт драйвер LCD.

Измерение аккумулятора допускает только `P0.02`…`P0.05` и `P0.28`…`P0.31`.
На выбранный вывод подключается середина прежнего делителя 1 МОм / 1 МОм
с конденсатором 100 нФ к земле. Коэффициент делителя остаётся 2;
`battery_voltage.calibration` задаёт небольшую поправку измерения.
В Bluetooth, если делителя нет, укажите это явно:

```yaml
gtag_display:
  battery_voltage:
    enabled: false
```

Для Zigbee подключите пакет **после** основного пакета:

```yaml
packages:
  gtag: !include packages/zigbee-base.yaml
  no_battery: !include packages/zigbee-no-battery.yaml
```

Он удаляет АЦП и датчик напряжения из Zigbee. Вариант объявляется как
`GTag_Display_Frame_NoBat`; обновлённые конвертер и интеграция HA не создают
для него сущность Battery voltage. Один `battery_voltage: {enabled: false}` выключает
АЦП, но оставляет шаблонный Zigbee-датчик — используйте пакет для полного отключения.
Для опубликованной версии оба пакета можно подключить через `github://` на одном
теге, как в [конфигурации Super52840](../config/esphome/gtag-super52840-zigbee.yaml).
При смене этого варианта на уже сопряжённой плате выполните повторное интервью
в Zigbee2MQTT и перезагрузите запись GTag в HA, поскольку состав endpoints меняется.
Ранее созданную сущность напряжения можно отключить в реестре сущностей HA.

`clk_pin` — тактовая линия передачи данных. Штатный сигнал **DisplayCLK/S1**
по-прежнему поступает от платы ценника и не переназначается этим параметром.
Прямые записи GPIO, порядок инициализации, импульс RESET 50 мкс и паузы LCD
сохранены. Тесты сравнивают поток слов после переназначения с записью ESP32.

## Super52840 и другие платы

Совпадение чипа само по себе не подтверждает совместимость готового UF2.
Перед первой прошивкой нужно сверить распиновку, наличие кварца 32 кГц
и загрузчик конкретной платы. Общий пакет сейчас использует профиль
`adafruit_itsybitsy_nrf52840`, загрузчик `adafruit_nrf52_sd140_v6`, начало
приложения `0x26000` и `dcdc: false`. Переназначение GPIO эти параметры не меняет.
Super52840 имеет отдельную конфигурацию:
[nrf-gtag-super52840-zigbee.yaml](../config/esphome/nrf-gtag-super52840-zigbee.yaml).
В ней измерение напряжения выключено; на первую плату её настройки не влияют.

| Сигнал LCD | Маркировка Super52840 | GPIO |
|---|---|---|
| DIO | D10 / 115 | P1.15 |
| CLK передачи данных | D8 / 113 | P1.13 |
| CS | D9 / 114 | P1.14 |
| RESET экрана | D7 / 112 | P1.12 |

Нужны общая GND, питание экрана по прежней схеме и сохранённое штатное
тактирование DisplayCLK/S1. Площадки `CLK`/`DIO` на обороте Super52840 относятся
к SWD-отладчику; для LCD используются GPIO из таблицы.

У проверенной платы `INFO_UF2.TXT`: `Seeed_XIAO_nRF52840_Sense`, загрузчик
0.6.1, S140 **7.3.0**. Ей задан `adafruit_nrf52_sd140_v7`, начало приложения
**0x27000**. Общий профиль сборки ItsyBitsy сохранён как техническая основа:
неиспользуемая периферия отключена. Для Super52840 нужен отдельный
`gtag-super52840-zigbee.uf2`; обычный `gtag-zigbee.uf2` предназначен для Pro Micro.
Профиль не заменяет загрузчик и не записывает его область.

Распиновка и наличие кварца 32,768 кГц сверены со
[схемой производителя](https://www.nologo.tech/assets/img/keyboard/keyboard_controll/super52840/6.png).
В этой схеме также показан делитель 1 МОм / 510 кОм на P0.31 с управлением P0.14;
он отличается от внешнего делителя проекта. В профиле Super52840 измерение
выключено, поддержка этого встроенного делителя не реализована.

18 сентября 2026 плата прошита, присоединилась к Zigbee2MQTT как
`0xf4ce36b5dc3ea251`, успешно прошла интервью, датчика напряжения в exposes нет.
После подключения второго LCD пользователь подтвердил корректное отображение:
оба Zigbee-экрана одновременно выводят разные показатели из HA. Потребление
Super52840 пока не измерено.

Для сборки из GitHub используйте публичные YAML на теге `v1.0.0`;
для локальной разработки — конфигурации `nrf-gtag-*.yaml` и исходники компонента.
Готовые `gtag-display.uf2` / `gtag-zigbee.uf2` используют прежнюю распиновку;
`gtag-super52840-zigbee.uf2` — таблицу выше. Для своей разводки соберите свой UF2.

## Проверка двух устройств

Для каждого устройства создайте отдельную конфигурацию ESPHome с уникальным
`gtag_name`. В Zigbee2MQTT устройства различаются по IEEE-адресу, а в HA
добавляются отдельными записями интеграции. Каждое получает собственные
макет, настройки актуальности, превью и показания батареи.

Автоматические тесты проверяют адресацию `draw`, разные макеты и батареи,
отдельные подтверждения кадров и актуальности, применение настроек,
перезагрузку одной записи и работу второго экрана при потере первого.
Конвертер отдельно проверен на передачу второму устройству, пока первое
не отвечает. Радио в этих тестах моделируется.

Пользователь подтвердил подключение двух физических плат, вывод разных
показателей, восстановление после перезапуска HA/Zigbee2MQTT с сохранением
настроек и независимую работу при отключении/включении одной из плат.
Полный перечень сценариев:

1. Подключить второй экран по его YAML и добавить устройство в Zigbee2MQTT и HA.
2. Выбрать разные макеты, затем обновить оба одновременно; сверить оба LCD и превью.
3. Изменить макет и срок актуальности одного — настройки второго должны сохраниться.
4. Отключить связь одного; второй должен продолжить обновления. Вернуть первый
   и дождаться восстановления без перезапуска.
5. Перезагрузить HA/Zigbee2MQTT и проверить оба экрана и сохранённые настройки.

Успешный тест одного устройства или программные тесты не заменяют эту проверку.
