# GTag Zigbee frame protocol v1

Модель `GTag_Display_Frame_V1`, HA profile `0x0104`, endpoint 4,
server cluster `0xFC11`. Конвертер ищет endpoint по входному кластеру.
Endpoints 1–3 сохраняют телеметрию и диагностику первого прототипа.

Вариант без АЦП объявляется как `GTag_Display_Frame_NoBat`: endpoint 1 —
счётчик кадров, 2 — тестовый узор, 3 — тот же frame cluster `0xFC11`.
Конвертер сохраняет MQTT-имена `rendered_frames_2` и `display_pattern_3`,
перенаправляя их на соответствующие физические endpoints; `battery_voltage_1`
не объявляется. Формат кадров и подтверждений одинаков для обеих моделей.

ZCL: cluster-specific, без manufacturer-specific поля. Client → server command
`0x00` (`packet`), server → client response `0x80` (`reply`) с той же transaction
sequence number. Полезная нагрузка — один `OCTET_STR`: байт длины, затем пакет.
Координатор отключает default response и ждёт именно ответ `0x80`.

## Запросы

Все многобайтовые числа little-endian. Первый байт — opcode.
Сессия — случайный 32-битный идентификатор кадра.

| Opcode | Содержимое после opcode | Длина пакета |
|---|---|---|
| 1 BEGIN | version:u8=1, codec:u8, encoded_size:u16, session:u32, raw_crc32:u32, freshness_timeout_s:u32 | 17 |
| 2 DATA | session:u32, offset:u16, data:1..32 bytes | 8..39 |
| 3 COMMIT | session:u32 | 5 |
| 4 STATUS | session:u32 | 5 |
| 6 FRESHNESS | session:u32, raw_crc32:u32, sequence:u32 | 13 |
| 7 INFO | Нет полей | 1 |

Перед BEGIN новый отправитель читает INFO: версию прошивки и список
поддерживаемых форматов. Ответ INFO — 43 байта, его схема описана в
[совместимости прошивок](firmware-compatibility.md). Исходный BEGIN 13 байтов
без срока актуальности сохраняется для режима legacy.

Кодеки и CRC совпадают с BLE: RAW=0, WHITE_RLE_V1=1, CRC-32/IEEE от
несжатого кадра 4096 байтов. DATA содержит смещение в **сжатом** потоке.
Пиксели упакованы в нативный формат LCD `row-lsb`: индекс байта `y*32+x/8`,
маска пикселя `1 << (x%8)`, 1 — белый. Это тот же формат, что у рендера HA.
Порядок пикселей внутри байта не следует путать с передачей битов слова
по проводному интерфейсу LCD, где D/C и байт передаются MSB-first.
DATA/COMMIT с чужой сессией отклоняются. STATUS возвращает активную сессию,
даже если запрос содержит другой идентификатор: так отправитель обнаруживает
перезапуск устройства. Входные длины проверяются до изменения приёмника.

Описание срока актуальности и повторов подтверждения: [freshness.md](freshness.md).

## Ответ на BEGIN/DATA/COMMIT/STATUS/FRESHNESS: 20 байтов

| Смещение | Размер | Значение |
|---|---|---|
| 0 | 1 | Версия = 1 |
| 1 | 1 | Opcode запроса |
| 2 | 1 | Result: 0 OK, 1 BUSY, 2 INVALID, 3 SESSION, 4 RECEIVER |
| 3 | 4 | Активная сессия |
| 7 | 1 | Состояние: 0 IDLE, 1 RECEIVING, 2 COMPLETE, 3 ERROR |
| 8 | 2 | Принято байтов сжатого потока |
| 10 | 4 | CRC приёмника |
| 14 | 1 | Ошибка общего frame::Receiver, 0 = нет |
| 15 | 1 | Flags: bit 0 — ожидается вывод на LCD; bit 1 — выведен проверенный кадр; bit 2 — на LCD показан значок устаревания |
| 16 | 4 | Идентификатор последнего выведенного проверенного кадра |

COMPLETE подтверждает декодирование и CRC, но **не** завершение вывода.
Отправитель ждёт bit 1, совпадения последнего выведенного идентификатора
со своей сессией и снятия bit 0. Диагностический рисунок снимает bit 1.
При BUSY/INVALID, сформированном самим радиообработчиком, поля состояния могут
быть нулевыми: сначала нужно оценивать Result.

## Повторы и потоки исполнения

Повторный BEGIN с тем же описанием возобновляет приём. Повторный DATA с уже
принятым совпадающим префиксом допустим. Повторный COMMIT не выводит кадр снова,
если он уже выведен; после диагностического рисунка тот же кадр можно восстановить.
Новое описание BEGIN отклоняется как BUSY, пока предыдущий кадр ожидает LCD.
Повреждённый кадр не заменяет подготовленный правильный кадр.

ZBOSS передаёт ограниченный пакет в один слот, будит цикл ESPHome и удерживает
входной буфер до ответа. Парсинг кадров, CRC и GPIO выполняются в основном
цикле. Ответ планируется через thread-safe `zigbee_schedule_callback`;
операции с буферами ZBOSS остаются в потоке Zigbee. Дополнительный входящий
пакет при занятом слоте получает BUSY.

Конвертер отправляет блоки по 32 байта последовательно. На запрос — до четырёх
попыток с таймаутом 8 секунд. При потере сессии разрешён один перезапуск BEGIN;
новые попытки прекращаются через 180 секунд (уже начатый запрос может ждать
свой таймаут). После COMMIT — до 30 чтений подтверждения вывода.
Пакеты используют `sendPolicy: immediate`, чтобы ошибка радиодоставки
возвращалась конвертеру, а не оставляла пакет в очереди herdsman до check-in.
На один IEEE-адрес одновременно разрешена одна передача. Разные устройства
имеют отдельные блокировки. Прерванный приём сохраняется в RAM до следующего
BEGIN или перезапуска; отменённую передачу пока нужно заменить новым кадром.

Спящий профиль опрашивает родителя каждые 3 секунды. После успешных BEGIN/DATA
и промежуточных COMMIT/STATUS он запрашивает адаптивный Turbo Poll ZBOSS
на один следующий пакет. Финальный STATUS, повторный COMMIT уже показанного
кадра, FRESHNESS и ошибки этот режим не продлевают. При остановке передачи
ускоренный опрос завершается автоматически. Формат кадров одинаков
для спящего профиля и постоянного приёма. Результаты радиоиспытаний и порядок
замера тока описаны в [руководстве прототипа](zigbee-prototype.md).

Протокол пока экспериментальный. Интеграция HA 0.9.0-beta.1 использует
этот конвертер через MQTT; [формат команд и установка](zigbee-home-assistant.md).
Идентификатор `frame_request_id` связывает MQTT-команду с её подтверждением
и не меняет радиопротокол или 32-битный идентификатор Zigbee-сессии.

## Опциональная диагностика питания

При `gtag_display.zigbee_power_diagnostics: true` радиообработчик принимает
однобайтовый запрос `05` (opcode 5) независимо от буфера изображения. Ответ
идёт той же командой ZCL `0x80`, но содержит **40 байтов** OCTET_STR:

| Смещение | Тип | Значение |
|---|---|---|
| 0 | u8 | Версия = 1 |
| 1 | u8 | Opcode = 5 |
| 2 | u8 | Result = 0 |
| 3 | u8 | Flags: bit 0 RX-on-when-idle, bit 1 joined |
| 4 | u32 | Uptime, мс |
| 8 | u32 | Фактическое время внутри SDK `zb_osif_sleep`, мс |
| 12 | u32 | Число вызовов `zb_osif_sleep` |
| 16 | u32 | Время системного idle, мс |
| 20 | u32 | Время потока main, мс |
| 24 | u32 | Время потока zboss, мс |
| 28 | u32 | Число аппаратных снимков |
| 32 | u32 | Снимки с `NRF_RADIO.STATE == Disabled` |
| 36 | u32 | Снимки с кварцевым источником HFCLK |

Все счётчики отсчитываются с запуска и передаются little-endian; 32-битные
значения переполняются по модулю 2³². Запрос не меняет состояние кадра и не
включает ускоренный опрос. В сборке без опции opcode 5 возвращает обычный
20-байтовый ответ с ошибкой INVALID; конвертер сообщает о неподдерживаемой
диагностике. Проценты следует вычислять по разности двух снимков, учитывая
перезапуск устройства и ограничения дискретного опроса аппаратных регистров.
